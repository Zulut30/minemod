## Новый проход

Вместо следующей общей правки масштаба созданы три самостоятельных силуэта: A — асимметричный полярный тесак, B — кристальный страж с массивной гардой, C — тёмный кованый палаш с горячей кромкой. Для поиска направления получен оригинальный концепт через image_gen. Это иллюстрация для авторинга; геометрия и пиксельная текстура созданы Codex отдельно как редактируемые данные. Автоматического image-to-3D преобразования в приложении нет.

Источник — `fixtures/assets/weapon-directions.mjs`. Атлас 128×128, палитра 18 цветов, около двух текселей на единицу поверхности. Для каждой грани есть собственный UV с продолжением крайних цветов в padding. Крупные цветовые группы, широкие скосы, отдельный объёмный акцент у основания и более толстые рукояти заменяют мелкие руны. После первого просмотра устранены полосы от отдельного затенения каждой ступени и уточнены соединения гнёзд кристаллов с корпусом.

Авторский runner `apps/model-editor/scripts/create-weapon-directions.mjs` создаёт новый проект, сохраняет отвергнутую модель и три новых варианта, экспортирует JSON/PNG/Blockbench, открывает проект в отдельном скрытом экземпляре настоящего EXE и получает четыре обзора и 16 снимков через закрытый HTTP MCP. Он не управляет пользовательским окном и не передаёт исполняемый код через MCP. SHA-256 экспорта MCP сверяется с отдельным application service; исходный проект сохраняется.

```powershell
corepack pnpm --filter @mcdev/model-editor package
node apps/model-editor/scripts/create-weapon-directions.mjs output/model-editor/weapon-redesign-review C:/path/to/original-concept.png
```

Нужны зафиксированные Node 24.11.0, pnpm 11.8.0 и установленные workspace-зависимости. Путь концепта передаётся явно; результат должен находиться в `output/` этого проекта. Название каталога выбирайте новым для каждого прохода.

## Маленькие превью 0.5.1

Прежняя миниатюра уменьшала целый широкий viewport до 64×64, вместе с пустым пространством по сторонам. Теперь модель отдельно рендерится GPU в квадратную текстуру 64×64 с общим кадрированием сравниваемых вариантов. Размер предмета не зависит от ширины панели; прозрачность, пиксельная фильтрация и sRGB сохраняются. Камера основного viewport не меняется. Превью 32×32 получается из этого рендера с nearest sampling. Это предпросмотр редактора, а не воспроизведение игрового GUI transform.

Desktop-проверка измеряет заполненную высоту силуэта и заставляет новый рендер после изменения материала и undo в компактном окне: квадратная миниатюра должна восстановиться байт в байт при другом соотношении сторон панели. Проверяются также обновление после правок, отсутствие мутации ручной камеры и прежние сценарии редактора.

## Следующая художественная итерация

Если пользователь отвергает весь дизайн, сначала нужны разные силуэты. Сравнивать только оттенки и общий масштаб одного предмета недостаточно. Оцените реальные модели рядом и отдельно в чёрном силуэте; затем доработайте выбранное направление. Не превращайте каждую ступень геометрии в отдельную полоску текстуры. Крупный материал и акцент должны читаться до мелких сколов и обмоток. Новые части не обязаны повторять прошлый дизайн; закрепления существующего проекта остаются обязательными для агента.

Не объявляйте новую модель хорошей заранее. Концепт, технический PASS, визуальные наблюдения Codex, решение пользователя и подтверждение работы в Minecraft — разные результаты. Текущие варианты остаются DRAFT. Проверка в игре, формальная art rubric и интеграция в JAR ещё не выполнены; trusted pack не изменяется.

Ограничения формата сверены через Context7 и официальные исходники [Blockbench Java export](https://github.com/JannisX11/blockbench/blob/master/js/formats/java/java_block.js). Квадратный рендер использует документированные [WebGLRenderTarget](https://threejs.org/docs/pages/WebGLRenderTarget.html), [WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer.html) и [OrthographicCamera](https://threejs.org/docs/pages/OrthographicCamera.html). Новые зависимости и чужие assets не добавлены.
