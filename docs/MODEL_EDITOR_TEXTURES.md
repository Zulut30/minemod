# Пиксельная мастерская MineMod Studio

Обновлено 4 октября 2026 года для 0.4.0. Локальная покраска и числовой UV editor реализованы; [варианты](MODEL_EDITOR_VARIANTS.md) сохраняют и сравнивают их состояние. Художественная beta, самостоятельные итерации обоими агентами и работа экспортированных ресурсов в Minecraft ещё не приняты.

## Ручной сценарий

1. Откройте пример меча и выберите часть в дереве. Перейдите в «Текстура / UV».
2. Выберите цвет из палитры или пипеткой. Кисть рисует квадратными пикселями, ластик делает пиксель полностью прозрачным. Заливка меняет связную область одного цвета внутри выделенных поверхностей.
3. Увеличьте масштаб до 400–1600%. Атлас прокручивается; «К выделению» центрирует выбранные UV. Оранжевые рамки обозначают доступную область, остальные пиксели затемнены. В 3D можно крупно рассмотреть выбранную часть или переключиться на весь предмет.
4. Рисуйте штрих: предпросмотр виден на атласе и в 3D под ним, документ меняется только после отпускания кисти. Ctrl+Z отменяет весь штрих. Esc, потеря указателя/фокуса, смена выделения или обновление проекта отменяют незавершённый штрих.
5. Для изменения UV выберите один куб и одну грань. Задайте U, V, U₂, V₂ и нажмите «Перенести UV и рисунок». Рисунок переносится вместе с прямоугольником, при изменении размера применяется ближайший пиксель. Плотность выводится в пикселях на единицу модели.
6. Сохраните проект и экспортируйте bundle. Проверьте PNG и модель с разных сторон; интеграция и проверка в игре выполняются отдельным этапом.

Покраска охватывает выбранные кубы и, при необходимости, только одну ориентацию грани. Выбор цвета в левой палитре открывает мастерскую. «Применить цвет» в свойствах остаётся отдельной операцией тонирования всей выбранной части с сохранением градаций яркости; кисть записывает точный RGB.

## Ограничения

- Атлас: поддерживаемые размеры 16/32/64/128/256 по каждой оси. До 32 реально используемых RGB-цветов; неиспользуемые цвета освобождаются при покраске. Частичная прозрачность и слои отсутствуют.
- Кисть: 1–8 пикселей, до 4096 уникальных точек за штрих. Быстрое движение заполняет промежутки целочисленной линией. Превышение лимита отменяет незавершённый штрих.
- Общие UV: изменение пикселя, который читает другая невыбранная поверхность, возвращает `SHARED_UV`. Это касается и разных граней одного куба. Перенесите одну грань в свободное место; её старые общие пиксели сохранятся для соседей.
- Новый UV-прямоугольник не пересекает чужие UV и оставляет отступ в один пиксель; иначе `UV_COLLISION`. Обратный порядок координат сохраняет ориентацию текстуры. Автоматическая перепаковка, вращение UV на 90° и drag-развёртка пока отсутствуют.
- Предпросмотр штриха — локальный draft. Ревизия агента имеет тот же контракт документа; при параллельном commit незавершённый ручной штрих отменяется. Повтор уже применённой команды безопасен благодаря UUID key.

Формат собственного проекта сохраняется: старые файлы открываются без миграции. Новых зависимостей в версии 0.3 нет.

## Команды агента

В [MCP adapter](MODEL_EDITOR_MCP.md) используются существующие `studio_changes_preview` → `studio_changes_apply`. `studio_project_inspect(includeTexture: true)` возвращает UV, палитру и строки пикселей.

Примеры отдельных команд внутри `commands` (реальные cube IDs и координаты нужно прочитать из текущей сцены):

```json
{"type":"paint","cubeIds":["guard_center"],"face":"north","color":"#ffeedd","size":1,"points":[[32,25],[33,25],[34,25]]}
```

```json
{"type":"fill","cubeIds":["guard_center"],"face":"north","color":null,"seed":[32,25]}
```

```json
{"type":"uv","cubeId":"guard_center","face":"north","rect":[200,200,211,204]}
```

`face` можно опустить для всех граней выбранных кубов. Названия: `north`, `south`, `east`, `west`, `up`, `down`. Команды ограничены схемами, ревизией, правами закреплённых частей и серверной проверкой; agent eval и произвольного доступа к canvas нет.

## Проверки

Core tests проверяют точные цвета соседей, прозрачность, связную заливку, границы, лимит палитры, общий UV, отражение/масштаб переноса, rollback batch, историю, закрепления и распакованный RGBA экспортированного PNG.

Desktop E2E проверяет реальные pointer events в скрытом Electron: локальный draft без изменения ревизии, обновление 3D до commit, один шаг истории, кисть/пипетку/ластик/заливку, отмену через Esc/pointercancel/lostcapture/blur, параллельное изменение настоящим HTTP MCP клиентом, смену проекта и перенос UV с отклонением пересечения. MCP tests дополнительно проверяют paint/fill/uv через два HTTP клиента; packaged E2E сохраняет снимки нескольких ракурсов.

Итоговый packaged отчёт 0.4.0: `output/playwright/studio-packaged-eb65476c/report.json`, PASS. В нём повторно проверены все RGBA экспортированной текстуры, одновременная видимость атласа, UV-инструментов и 3D при размере окна 1120×760 и восстановление после перезапуска. Сводка с hashes: `output/verification/STUDIO_BUILD-0.4.0.json`; оригиналы снимков остаются рядом с отчётом. Текущая сводка `STUDIO_BUILD.json` и копии снимков в `output/model-editor/screenshots/` относятся к [этапу 0.5](MODEL_EDITOR_DARK_AND_REVIEW.md). Окна тестов оставались скрытыми и были закрыты после проверки. Исправления сохранения описаны в [отчёте 0.3.2](MODEL_EDITOR_EDITING.md), восстановления — в [полировке 0.3.1](MODEL_EDITOR_POLISH.md).

Технические тесты и сохранённые снимки не подтверждают художественное качество. Полная приёмка M3 по [плану](MODEL_EDITOR_MVP_PLAN.md) включает отдельную работу над рисунком и оценку модели; игровой этап не выполнен.

При реализации сверены [React events](https://react.dev/learn/responding-to-events) и cleanup effects через Context7, [W3C Pointer Events](https://www.w3.org/TR/pointerevents3/#the-lostpointercapture-event), [WHATWG Canvas](https://html.spec.whatwg.org/multipage/canvas.html#dom-context-2d-imagesmoothingenabled-dev).
