# Варианты и визуальная итерация MineMod Studio 0.4.0

Актуализация 0.16.0: подключённый агент может добавлять до трёх ИИ-черновиков через `draftVariant`; восстановление, удаление и ручной checkpoint остаются у пользователя. Снимок всегда берётся из текущей сцены, существующие snapshots неизменны, новый blockout должен отличаться размещённой геометрией. Ни префикс черновика, ни техническое различие не являются художественной оценкой. Формат сохранения остаётся EditorProject v3; ранние ограничения ниже относятся к исторической 0.4. [Текущий workflow и доказательства](production/BLOCKOUT_DRAFTS.md).

4 октября 2026 года. Реализован следующий этап мастерской: задание для агента, независимые снимки модели и сравнение на одинаковых ракурсах. Это часть M5; самостоятельные model turns установленных Codex/Claude, художественная beta и работа в Minecraft остаются неподтверждёнными.

## Работа с вариантами

1. Перейдите на вкладку «Варианты». Опишите желаемый силуэт, палитру и детали в «Задании для агента», затем сохраните задание. Нужные части защитите замком в дереве: текст задания сам по себе не является запретом изменения.
2. Сохраните «Исходник» перед правками. Имя и заметка поясняют замысел; геометрия, UV, покраска и закрепления записываются отдельным снимком внутри проекта.
3. Изменяйте рабочую модель вручную или через MCP. Снимок исходника остаётся прежним. Сохраните результат как новый вариант.
4. Выберите снимок для сравнения. Слева находится сохранённая модель, справа — рабочая. Четыре фиксированных ракурса используют общие центр и масштаб, одинаковый свет; «Силуэт» убирает цвет, сохраняя прозрачность. Миниатюры 64×64 показывают тот же кадр.
5. «Редактировать этот вариант» переносит его геометрию, UV, покраску и закрепления в рабочую модель, сохраняя задание и все снимки. Возврат и удаление снимка можно отменить через undo. Текущую несохранённую работу перед возвратом полезно сохранить отдельным вариантом.
6. Нажмите «Сохранить» для записи всего проекта. История текущей сессии после перезапуска не восстанавливается; снимки и задание сохраняются, включая recovery.

Снимки являются неизменяемыми сохранёнными состояниями, а не несколькими одновременно редактируемыми документами. Переключение ракурсов в сравнении фиксированное; свободный orbit доступен в обычной вкладке «Модель». Предпросмотр редактора и уменьшенная картинка не заменяют игровой инвентарь.

## Контракт и ограничения

- До четырёх снимков. Они не содержат вложенных снимков. Один файл вместе с вариантами ограничен 1 MiB; проверка учитывает сохраняемые отступы и происходит до commit. При превышении сохраняется предыдущее состояние.
- `EditorProject v1` получил необязательный `design`: задание до 1200 символов, имя снимка до 48, заметка до 400. Старые проекты открываются. Файлы с `design` требуют версии 0.4 или новее; старый строгий reader 0.3 не поддерживает новые поля.
- С Studio 0.7.0 текущий формат — EditorProject v2. Существующие v1, включая `design` и snapshots, проходят [миграцию с точной original copy](production/PROJECT_MIGRATIONS.md); сохранённый v2 требует нового reader.
- Все операции проходят существующие revision/project ID/UUID и атомарный batch. Новые human-only команды: `brief`, `checkpoint`, `restoreVariant`, `deleteVariant`. Агент получает отказ `HUMAN_ONLY`, если пытается изменить задание или сохранённые варианты. Restore увеличивает ревизию и делает прежние предложения агента устаревшими.
- Экспорт продолжает принимать только геометрию и текстуру текущей рабочей модели. Задание и варианты не становятся игровыми ресурсами или исполняемым кодом.

## MCP

Доступны девять tools. `studio_project_inspect` возвращает задание и краткие сведения о снимках, без дублирования всех моделей. `studio_variant_inspect({projectId, expectedRevision, variantId, includeTexture})` читает один снимок с проверкой текущей ревизии.

Для пары снимков одной стороны вызовите `studio_view_capture` для рабочей модели с `compareToVariantId`, затем для сохранённой с `variantId`. Обе картинки используют границы рабочей и сохранённой моделей; `silhouette: true` даёт чёрный силуэт. Не изменяйте сцену между парными снимками: `expectedRevision` должен оставаться тем же. У каждого ответа есть идентификатор варианта, ракурс и количество реально отрендеренных кубов. Секрет и конфигурация клиента в проект не входят.

## Авторский пример и оценка

`scripts/create-design-study.mjs` в приложении воспроизводит авторский пример текущей сессии Codex через реальные HTTP MCP preview/apply/capture/validate/export. Созданы «Страж льда» с более широким коротким клинком и светлыми кромками и «Лунная игла» с более узким длинным клинком и холодной гардой. Рукоять и навершие закреплены. После просмотра бокового ракурса толщину узкого клинка увеличили с 0.9× до 1.2× исходной; это отдельная визуальная итерация.

Пример сохраняет исходник и оба варианта в `*.mmeditor.json`, команды, review manifest, экспортные bundle-ответы и 16 PNG: четыре ракурса каждого кандидата рядом с исходником при общем кадрировании. Это авторская работа текущего Codex с закрытыми командами, а не самостоятельный model turn установленного CLI. Проект и evidence лежат в `output/model-editor/design-study-*/`; точный актуальный каталог указан в `output/verification/STUDIO_BUILD.json`.

Моя визуальная оценка: широкая версия лучше передаёт массу клинка спереди; узкая сохраняет вытянутый силуэт, но боковая читаемость требует внимания. Руны и маленькие акценты теряют детали при уменьшении. Эти наблюдения не являются автоматическим score или human approval. Кандидаты остаются доступными для выбора и дальнейшей покраски; игровая/художественная приёмка не объявляется завершённой.

## Проверки и сборка

Документ описывает этап 0.4; его сводка и hashes сохранены в `output/verification/STUDIO_BUILD-0.4.0.json`. Текущая сводка `STUDIO_BUILD.json` относится к [тёмной теме и обзору 0.5](MODEL_EDITOR_DARK_AND_REVIEW.md), который сохраняет описанные здесь операции с вариантами.

Core проверяет независимость снимков, restore/undo/redo, запреты агента, уникальность ID, лимит количества и размера, rollback, malformed/nested data и сохранение. HTTP tests проверяют чтение снимка, краткий контекст, stale revision, неизвестный ID и запрет изменений агентом. Desktop E2E в скрытом Electron проверяет задания, четыре одинаковых камеры, соответствие миниатюр актуальному кадру, реальный силуэт, компактное окно, восстановление/undo, устаревшее предложение, MCP captures, запись и restart recovery. Это дополнительные десять сценариев к прежним проверкам редактора.

Проверяются чистая упаковка, lint, typecheck и реальный EXE; отчёт и hashes — в `output/verification/STUDIO_BUILD.json`. Новый package создаёт отдельный каталог `output/model-editor/releases/<версия>/<build-id>/MineMod Studio-win32-x64/`. Указатель `latest-build.json` содержит путь; tests отказываются использовать сборку другой версии. Открытая пользователем 0.3.2 не закрывалась; её EXE и app.asar проверены по прежним SHA-256 и остались прежними. Для запуска новой обычной версии сначала закройте старое окно: общий single-instance lock предотвращает одновременно открытые обычные редакторы.

Новых зависимостей нет. Windows CI job настроена, но hosted run не выполнен. Пять переносимых пакетов и редактор проверяются отдельно; прежние шесть ошибок общего Windows workspace из-за POSIX/Linux ограничений не устранены. Trusted packs, Java/JAR и авторизация пользователя не изменялись. Clean Fabric build, GameTests, dedicated server и интеграция authored ресурсов требуют отдельного игрового этапа.

Через Context7 сверены [React immutable state](https://react.dev/reference/rules/components-and-hooks-must-be-pure), [Three.js OrthographicCamera](https://threejs.org/docs/pages/OrthographicCamera.html) и официальный [MCP SDK 1.29.0](https://github.com/modelcontextprotocol/typescript-sdk/blob/v1.29.0/docs/server.md).
