# Проверка и полировка MineMod Studio 0.3.1

3 октября 2026 года. Проверены добавленные ранее asset contracts/exporters, CLI и stdio MCP, editor core, локальный HTTP MCP, Electron host/worker/preload, renderer, покраска/UV и переносимая сборка. Изменения этого этапа ограничены редактором, его проверками и документацией. Зависимости, trusted packs, Java-код и JAR не изменены.

## Исправления

| Проблема | Изменение и проверка |
| --- | --- |
| `app.quit()` останавливал worker до решения о сохранении | Worker завершается в `will-quit`; отмена выхода и отмена SaveDialog оставляют сервис работоспособным. Проверено в скрытом Electron с действующим close guard. |
| Повторное закрытие создавало несколько запросов сохранения | Один ожидающий диалог в общей очереди. Три вызова close дают один диалог. |
| Агент мог изменить проект во время диалога открытия/закрытия | Private host reference проверяется внутри очереди worker; устаревшая операция отклоняется. Перед разрешённым выходом сервис прекращает принимать изменения. Реальный HTTP клиент проверяет оба конфликта. |
| Отсутствующий recovery-файл исключал попытку загрузить `.bak` | Резервная копия проверяется и при ENOENT основного файла. Проверено восстановление документа при наличии только `.bak`. |
| Запуск мог заменить повреждённые recovery-файлы исходным примером | Init больше не записывает recovery. При отказе загрузки оба исходных файла сохраняются побайтно; запись начинается после правки документа. |
| Ответ команды скрывал предупреждение об отказе автокопии | Recovery warning передаётся отдельно от обычного статуса. Реальный отказ записи в изолированной тестовой папке сохраняет правку в памяти и оставляет доступным ручное сохранение. |
| Неудачное открытие сбрасывало выделение агента | Новая сцена и выделение заменяются только после успешного чтения. Повреждённый проект оставляет текущие данные и shared selection. |
| Фиксированный `.pending` мог перезаписать посторонний временный файл | Уникальное имя и exclusive open; удаление собственного temp при ошибке записи/rename. Чтение использует один file handle и буфер максимум 1 MiB + 1 байт. Проверены большой файл, чужой temp, отказ сохранения и сохранность валидной копии. |
| Пустое поле положения превращалось в ноль | Пустой ввод отменяется, Enter применяет значение, Esc возвращает текущее. Ввод привязан к revision/project ID; устаревшая правка отклоняется. E2E проверяет пустое положение без изменения документа. |
| Ctrl+S не работал внутри числового поля | Blur завершает ввод, сохранение ждёт команды. Добавлены «Сохранить как…» и Ctrl+Shift+S. E2E сравнивает сохранённую геометрию, копию и исходный файл. |
| В компактном окне 3D уходил ниже видимых UV-инструментов | Уменьшены боковые панели и отступы мастерской. При 1120×760 видны UV, атлас высотой 121.46 CSS px и 3D высотой 164.69 CSS px; внешнего overflow нет. |
| Упаковка могла использовать старый dist с новым номером версии | `package` выполняет чистую сборку; версия renderer и MCP берётся из manifest. Итоговый EXE имеет версию 0.3.1. Обычный запуск использует single-instance lock, чтобы два окна не делили recovery. |

## Подтверждённые проверки

- `lint` и `typecheck:all`: PASS, включая отдельные host/renderer конфигурации.
- Editor core: PASS — транзакции, rollback, история, locks, лимиты, изоляция пикселей, прозрачность, заливка, UV-перенос и точные RGBA экспортированной PNG; дополнены проверки файлового сохранения.
- HTTP MCP: PASS — два SDK-клиента, Bearer/Host/Origin, лимиты UTF-8, strict schema, preview, конфликты, replay, locks, человеческая история и экспорт.
- Чистая desktop сборка и упаковка: PASS; лицензии всех 19 bundled runtime packages включены.
- Итоговый EXE: PASS — реальный WebGL, GUI/агентная общая сцена, покраска, undo/redo, UV, кириллица в путях, экспорт и восстановление; дополнительно 13 сценариев файловых диалогов/выхода. Данные и native dialog mocks изолированы. Все окна скрыты, Computer Use и управление рабочим столом не применялись.
- Установленный Codex CLI 0.143.0: PASS через реальный app-server MCP inventory и tool calls. Установленный Claude Code 2.1.226: PASS регистрации и HTTP health. Самостоятельные model turns и Claude tool calls не запускались.

Evidence сборки 0.3.1: `output/playwright/studio-packaged-e1b5ff37/report.json`, отдельные сценарии — `polish/report.json` рядом. Сводка и SHA-256 этой версии сохранены в `output/verification/STUDIO_BUILD-0.3.1.json`; оригиналы всех ракурсов остаются рядом с отчётом. Логи этапа имеют префикс `output/verification/studio-polish-`. Текущая версия, сводка `STUDIO_BUILD.json` и копии снимков в `output/model-editor/screenshots/` обновлены в [этапе 0.5](MODEL_EDITOR_DARK_AND_REVIEW.md).

## Ограничения общего прогона

Входной `pnpm -r --no-bail --if-present test` дал 13 PASS / 6 FAIL. Четыре ошибки связаны с trusted-pack проверкой Linux execute mode: у `packs/fabric-1.20.1/runtime/templates/gradlew` размер 9671 и SHA-256 `edeebb8b7ddcd62dc39d85846bf93bc016da6a644bf7489fad47c3d6c02ad0ad` совпадают с manifest, но Windows возвращает 0666 вместо 0755. Аналогичное совпадение байтов/hash и несовпадение mode подтверждены для Fabric 26.2 и NeoForge 26.1.2; evidence — `output/verification/studio-polish-pack-modes.json`. `workspace` требует POSIX ownership; `build-runner` явно поддерживает Linux x64. Эти guards не отключались, manifest и trusted hashes не менялись. WSL сообщает `REGDB_E_CLASSNOTREG`; Linux-прогон в этой среде недоступен.

После полировки повторены перечисленные проверки редактора. Остальные пакеты не объявляются повторно проверенными. Общая suite остаётся с шестью ошибками Windows; зелёный игровой pipeline этим отчётом не подтверждается.

Clean Fabric build, GameTests, dedicated-server и визуальная проверка ресурсов в Minecraft не выполнены. Интеграция authored asset bundle в ModSpec/JAR ещё не реализована. Художественная приёмка и автономная работа обеих моделей остаются отдельными этапами.

## Документация, сверенная при исправлениях

Порядок выхода сверён через Context7 и официальную [документацию Electron app](https://www.electronjs.org/docs/latest/api/app#event-before-quit). Чтение, exclusive open и fsync — по [Node.js 24 fs](https://nodejs.org/docs/latest-v24.x/api/fs.html). В рабочем прогоне использован закреплённый Node.js 24.11.0; новых зависимостей не добавлено.
