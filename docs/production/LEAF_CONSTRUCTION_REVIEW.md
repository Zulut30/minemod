# «Лист»: конструкция и следующий проход формы

Этапы 044–046 открыты. Это измерения и наблюдения агента по двум существующим черновикам, без художественной приёмки. Direction A выбран пользователем; узнаваемость маленького силуэта, объём и текстура ещё не приняты.

Bounds учитывают cube pivot, XYZ rotation и inflate. Граф учитывает повёрнутые boxes, касание/пересечение и численную epsilon `1e-12`. Он показывает связь геометрических объёмов; контакты по грани, ребру или точке не различаются. Texture alpha, площадь реального стыка, объём пересечения, центр тяжести и достаточность крепления здесь не определяются. Одна компонента не заменяет проверку поверхностей и назначения деталей.

API проверены через Context7 и официальную [OBB документацию Three.js](https://threejs.org/docs/pages/OBB.html). Используется уже закреплённый Three.js 0.186.1, MIT; dependency/lockfile прежние. Scripted probes проверяют face contact, gap, разнесённые повёрнутые тонкие boxes, аналитический поворот вокруг смещённого pivot и inflate.

## Видимые места для правки

На правом виде B клинок имеет последовательность горизонтальных ступеней толщины; центр гарды и основание выделяются более тяжёлой полосой. В задней перспективе широкая плоская поверхность гребня окружена повторяющимися уступами. Верхний вид также показывает ступенчатое поперечное сечение. OBB-граф не обнаруживает отдельной висящей компоненты, но эти PNG не дают основания принять объём.

Следующий geometry-only черновик должен сгладить переход от гребня к кромке, уменьшить резкий скачок толщины у основания и сохранить симметрию выбранного направления A. Силуэт потребуется снова сопоставить с исходным вариантом на общих front/perspective 32/64 PNG. Детали и текстура добавляются после проверки формы; новый объём остаётся DRAFT до review. Количество кубов не является целью этого прохода.

## Черновик C: широкие скосы v4c

Отдельный developer recipe `apps/model-editor/scripts/create-leaf-bevel-draft.mjs` создаёт новый ИИ-черновик через закрытые editor-core команды, сохраняет прежние два snapshots и экспортирует все три варианта. Исходные A/B JSON и их concept sidecars остаются прежними. Это локальный авторский эксперимент одного меча; самостоятельная генерация внешним CLI-агентом и общий construction gate не заявляются.

Клинок C имеет четыре наклонных грани каждого сечения, с нативными Y-поворотами ±22.5°. Центральная плоскость и тонкая полоса заполняют сечение; внутреннее перекрытие cuboids задано намеренно. Пробный вариант ±45° оставлял слишком широкую плоскую середину и сохранён отдельно в output. В v4c уменьшены центр гарды, кольца и толщина основания; длина клинка приведена к заданной высоте модели.

29 768 аналитических проб проверили заполнение сечений и отсутствие выступов за заданный выпуклый профиль. SAT-проверка с исключением контактов только по ребру/точке дала одну компоненту и 265 контактов. Три заданных отношения размеров проходят проверку; world bounds помещается в номинальные 8×24×3. Полная ArtSpec conformity остаётся открытой: нейтральный материал, кристальный акцент, окончательная палитра и provenance review ещё не завершены.

Studio 0.19 снял восемь видов, обзор и силуэты: 48 PNG трёх вариантов, включая отдельные native 32/64. Framing и фактические камеры совпадают. Все native A/B PNG совпали с предыдущей проверкой S1/S2; исходный вопрос о читаемости остаётся привязан к прежним данным. Офлайн-страница с тремя кандидатами проверена скрытым браузером при ширинах 1400/390 и DPR 1/1.75, включая download JSON со scripted probe. Человеческое наблюдение этим не заменяется.

На снимках C видны скосы с обеих сторон и более собранная гарда. Цена выбранного cube budget — восемь основных сечений и три ступени острия: контур стал грубее B с восемнадцатью полосами края. Горизонтальные переходы и их читаемость требуют художественного сравнения. C остаётся DRAFT, этапы 044–046 открыты; форма, текстура и игровые представления не приняты. Assets в JAR не добавлялись.

Локальный результат: `output/model-editor/leaf-bevel-94fbca11/reviews-d33eecf4/comparison.html`; редактируемый C — `../c.mmeditor.json` с одноимённой `.assets` папкой. Проверяемые source hashes, экспорт, измерения и PNG записаны в [evidence 044](evidence/leaf-bevel-044.json).

```powershell

```

Runner требует сохранённые A/B JSON с точными SHA-256 выше и их concept sidecars. Он создаёт новую output-папку при каждом запуске. UUID и пути различаются; исходные snapshots и геометрический рецепт сохраняются. Эти локальные результаты не поставляются как release assets.

Скрипт измерений разделён на расчёт ориентированного box/world bounds, построение связей, контакты частей и сбор отчёта. Прежние аналитические probes проходят; итоговый A/B JSON побайтово совпадает с результатом до правки, SHA-256 `170b2a5719fb04c74d87940016ae13af02606c1a9a3c0693af5b110ca4b95474`. Общий lint PASS. [Проверка сохранения поведения](evidence/leaf-construction-readability.json) связывает вывод с конкретными bytes скрипта.

## Воспроизведение локального исследования

```powershell
node --experimental-strip-types apps/model-editor/scripts/measure-leaf-construction.mjs
```

Из корня репозитория нужны локальные A/B `.mmeditor.json` в `output/model-editor/leaf-volume-20261005-v3c` с ролями `blade_group`/`handle_group`. Скрипт читает их через bounded project parser, сохраняет source SHA-256, контакты и размеры в `output/verification/leaf-construction-044.json` и проверяет сохранность исходников. Статус `MEASURED` означает выполненные измерения. Это developer study одного оружия, без нового MCP endpoint, универсального construction gate для всех классов или authored game/JAR integration.
