# Точные правки геометрии

Roadmap 024. Studio 0.8.0 добавляет числовой центр вращения и привязку к сетке в существующий held-item editor. Формат проекта остаётся v2; новые операции не требуют переписывания сохранённых моделей. Блоки и произвольные mesh/rig-повороты этим изменением не добавляются.

## Ручной сценарий

1. Выберите часть или куб. «Положение» и «Размер» показывают габариты исходных кубов до поворота, в единицах Minecraft.
2. Выберите «Свободно» либо шаг 0.125, 0.25, 0.5 или 1. По умолчанию ввод свободный. При заданном шаге новая числовая координата или размер округляется на этот шаг; половина шага округляется от нуля, симметрично для положительных и отрицательных координат.
3. «Выровнять положение» переносит начало всего выделения на сетку. Размеры кубов, расстояния между ними, повороты, UV и рисунок сохраняются. Это не обещает, что каждый край каждого куба окажется на сетке.
4. Поля «Центр вращения X/Y/Z» показывают общий pivot; пустое поле с «Разные» означает разные значения. Ввод одной координаты задаёт её всем выбранным кубам и сохраняет две остальные координаты каждого куба. Escape отменяет ввод, включая смешанные значения. Enter применяет ввод; свободный режим сохраняет значащие цифры без округления интерфейсом до трёх знаков.
5. Выберите ось и угол, примените поворот. Для native item допускаются только 0°, ±22.5° и ±45° по одной оси. Поворот задаётся абсолютным значением и заменяет прежний. Смена pivot уже повёрнутого куба меняет его видимое положение; она не компенсируется скрытым переносом исходной геометрии.

Интерфейс заранее показывает ограничения: `from/to` с учётом `inflate` должны находиться в −16…32, координаты pivot — в −128…128. Ограничение `from/to` относится к исходным cuboids; оно не является проверкой world-space collision/hitbox после поворота. Некорректная правка отклоняется целиком. Ввод не применяется к изменившейся во время редактирования revision (`STALE_REVISION`).

## Публичный контракт для агента

Существующие `studio_changes_preview`/`studio_changes_apply` принимают новые команды через общую `MutationSchema`:

```json
{ "type": "pivot", "cubeIds": ["guard_center"], "axis": "x", "value": 8.125 }
```

```json
{ "type": "snap", "cubeIds": ["guard_center"], "step": 0.25 }
```

Schema tools/list включает ограниченный набор шагов и числовой диапазон pivot. Действуют прежние bytes/commands/targets limits, revision/CAS, atomic preview, replay keys, запрет агенту менять закреплённые части и отменять ручные операции. Snap использует server-side вычисление группового переноса; произвольные матрицы и eval не принимаются. Новые команды входят в undo/redo, а rejected batch не меняет проект, revision и историю.

## Проверка результата и границы

- Core проверяет групповой перенос, отрицательные half-step, точный pivot, сохранение размеров/интервалов/PNG/UV, untouched parts, locks, atomic failure и bounds с inflate. Native JSON содержит правильные `rotation.origin`, `axis`, `angle`, `rescale: false`; полная отмена и повтор возвращают точные hashes всех четырёх bundle files.
- Hidden packaged E2E использует настоящие числовые поля, Escape/Enter, кнопку поворота и undo/redo. Через реальный HTTP MCP проверены schema, preview/apply новых команд, stale pivot input, invalid step/angle и экспорт. Front PNG после полной отмены совпадает с исходным; capture после правки отличается.
- Регрессия трёх последовательных captures выявила и исправила race: обновление shared view/frame до доставки нового snapshot больше не оставляет камеру от прежней геометрии. Кадрирование зависит от конкретного capture job ID. Числовое поле сохраняет введённый draft при внешнем изменении той же координаты; CAS сообщает о конфликте вместо незаметного remount поля.
- Fabric 1.20.1 clean build/GameTests/dedicated-server подтверждаются отдельным CI. Editor render и корректный item JSON не подтверждают художественное качество или вид этого нового предмета в игре. Bundle продолжает требовать review перед игровой интеграцией.
