# Продолжение работы со сценой

Roadmap 039, Studio 0.17.0. Пользователь может приостановить доступ AI и продолжить его с тем же endpoint и token. Пауза доступна даже при ожидающем снимке или сохранении. Она не завершает внешний Codex/Claude Code и не откатывает уже применённую атомарную правку.

Пауза отменяет ожидающие tool calls и native capture, удаляет прежние proposals и повышает внутренний access epoch. Новые tools возвращают `AGENT_PAUSED`. `studio://scene/v1` остаётся читаемым и сообщает `agentAccess.state/epoch`, текущие projectId и revision. После продолжения нужно прочитать сцену и подготовить новый preview; proposal до паузы не становится действительным снова.

При `initialize` сервер выдаёт стандартный `Mcp-Session-Id` и сохраняет отдельный MCP server для этого клиента. Поэтому `notifications/cancelled` из SDK доходит до ожидающего запроса. Одинаковые JSON-RPC IDs в разных сессиях не пересекаются. Повтор активного ID внутри одной сессии отклоняется HTTP 409. Закрытие собственного HTTP response отменяет только его запрос. Headerless stateless POST сохраняет совместимость, но отдельная stateless notification не отменяет другой POST по совпавшему ID.

Отмена — best effort: перед выполнением очереди проверяются signal, epoch и revision. Синхронное применение транзакции заканчивается целиком. При отмене native capture удаляются waiter, timer и соответствующее скрытое окно; запоздавший ответ старого снимка не заменяет новый. Пауза/stop проходят приоритетно через renderer, main и worker, не вставая за обычным сохранением. Обычные изменения по-прежнему используют общую очередь.

Границы повторного запроса:

- После reconnect прочитайте живые IDs/revision. Точный уже применённый payload с прежним UUID key повторяет результат без нового куба или history entry; другой payload с тем же key получает `KEY_CONFLICT`.
- Replay cache хранит последние 100 ключей текущего `EditorSession`. Он не является журналом транзакций на диске и не переживает перезапуск процесса или смену документа.
- Ручная правка делает подготовленное proposal устаревшим. Открытие, новый документ и пример продолжают runtime revision с предыдущего значения +1, даже если сохранённый projectId тот же. Старое proposal удаляется, старый payload получает conflict.
- Stop и перезапуск приложения меняют token/endpoint. Автоматически возобновлять внешний AI-сеанс или повторять его запросы приложение не обещает.

Сессии ограничены: максимум 8, idle TTL 900 секунд, максимум 1024 обычных HTTP POST на сессию. После исчерпания лимита сервер возвращает 429 и закрывает освобождённую сессию; дальнейший вызов получает 404, нужен новый `initialize`. `DELETE` завершает свою сессию. GET SSE не предоставляется: сервер отвечает JSON, события изменения сцены нужно получать свежим чтением.

Обычный предел — 8 одновременных запросов и 120 в минуту. Ещё 2 одновременных места и 8 запросов в минуту доступны для отмены существующего запроса своей сессии и DELETE. Это позволяет освободить заполненную очередь. Byte/header/auth/Host/Origin и общий предел запросов сохраняются. В SDK 1.29.0 отменённый JSON request сам не завершает HTTP response: wrapper завершает его пустым 202, а lifetime/idle limits ограничивают оставшийся transport bookkeeping до закрытия сессии. Private поля SDK не изменяются.

Проверки используют настоящий HTTP SDK и собственный скрытый packaged EXE: отмена queued apply и native capture; заполненная очередь; два клиента с одинаковыми IDs; caps/idle/DELETE; GUI pause при ожидающем Save; resume/replay; CAS после ручной правки и повторного открытия; restart с сохранённым исходником и отключённым доступом. Mock capture в unit-проверке отделён от реального native PNG 1024×768 в desktop-проверке. Самостоятельный новый model turn Codex/Claude Code этим отчётом не подтверждён; художественная и игровая приёмка модели не присвоены.

Источники протокола: [SDK 1.29.0: cancellation](https://github.com/modelcontextprotocol/typescript-sdk/blob/v1.29.0/docs/protocol.md), [Streamable HTTP transport](https://github.com/modelcontextprotocol/typescript-sdk/blob/v1.29.0/src/server/webStandardStreamableHttp.ts), [официальная cancellation specification](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/cancellation). Использование сверено через Context7 и установленный SDK; новых dependencies нет.

Evidence точной source revision, локального пакета и hosted проверок будет добавлено после завершения прогонов. Пункт 039 до этого остаётся открытым.
