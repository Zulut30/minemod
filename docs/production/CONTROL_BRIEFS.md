# Контрольные брифы v1

Roadmap: пункт 005. Входные данные: [control-briefs.v1.json](../../fixtures/production/control-briefs.v1.json).

В наборе пять оригинальных заданий: оружие, броня, строительный блок, декоративный алтарь и существо Tidecaller. Общий target — Fabric 1.20.1 / Java 17; стиль задан пожеланием пользователя: выразительный Minecraft с пиксельной текстурой и продуманным силуэтом. Геометрия и чужие assets не включены.

Каждый бриф фиксирует ID, исходный prompt, требуемую capability, материалы, palette, ресурсный бюджет, обязательные captures, признаки приемлемого результата, негативные признаки и одну адресную repair-задачу. Брифы задают контрольный вход; они не являются ModSpec, ArtSpec, approval или реализованным runtime profile.

## Порядок повторения

- Записать hash исходного JSON, точные app/client/model/pack версии и параметры сеанса. Недоступные сведения обозначить `unknown`, а не придумывать.
- Подать неизменённый prompt и constraints через public agent workflow. Для оружия сначала три blockout; сохранять все результаты, а не только лучший.
- Снять указанные реальные editor/game captures, сохранить editable source, exports и hashes. Указать gaps, если требуемая capability не реализована; не заменять block на held-item или wearable armor на иконку.
- Применить repair-задачу к выбранному варианту и подтвердить сохранение заданных деталей, рисунка и rig.
- Человек оценивает применимые критерии rubric по точным артефактам. Контрактное отклонение и слабый художественный результат записываются отдельно.
- Повторить на сравниваемой версии системы с тем же входом. Изменение prompt, бюджета или palette создаёт новую benchmark version, а не переписывает старый результат.

Бюджеты здесь являются заранее заданными ограничениями benchmark, а не доказательством художественного качества. Повышать их задним числом ради прохождения теста нельзя; нужен новый согласованный ArtSpec/benchmark version.

## Приёмка пункта 005

JSON декодируется; ровно пять уникальных IDs и классов; prompts/repair/captures/acceptance/reject непустые; budgets не превышают текущие общие cuboid/palette/atlas limits. Данные позволяют повторить одинаковые задания и явно выявляют ещё не реализованные capabilities.
