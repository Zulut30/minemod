# Человек и агент: защита ручной правки

Roadmap 029. Мутации используют `projectId`, `expectedRevision` и UUID key. MCP сначала сохраняет проверяемое proposal, затем применяет его к исходному проекту и revision. Preview не меняет активный проект; устаревшая revision возвращает `REVISION_CONFLICT`, смена проекта — `PROJECT_CONFLICT`.

Отказ оставляет ручное состояние и revision неизменными. Для пересчёта агент читает актуальный проект и создаёт новое proposal с новым key. Старое proposal не переносится автоматически на свежую сцену. Повтор успешного apply с тем же proposal не применяет действие повторно. Последовательная worker queue и CAS обслуживают и human IPC, и MCP mutations.

Проверка упакованного Studio расширена реальным конфликтом SDK-клиента и human IPC:

1. Агент готовит proposal перекраски на прежней revision; текущий проект не меняется.
2. Human IPC применяет ручную перекраску, повышая revision.
3. Прежний proposal отклоняется; полный результат inspect, включая проект и revision, совпадает с ручным состоянием.
4. На ручном состоянии создаётся и применяется свежий proposal. GUI показывает изменение агента; повтор apply не увеличивает revision.
5. Undo агента возвращает новую ручную правку. Только отдельный human undo возвращает исходный проект.
6. Агент не может отменить human history или изменить закреплённую часть.

Результат: [packaged E2E и source hashes](evidence/revision-conflicts-029.json). Тест использует настоящий локальный MCP HTTP transport и trusted renderer IPC в собственных скрытых окнах. Он не является самостоятельным сеансом установленного Codex/Claude Code; подключение и качество их решений остаются отдельными пунктами 031/032.

Автоматического merge конфликтующих геометрических/пиксельных правок нет. Такой merge не требуется для безопасности: пользовательская версия сохраняется, агент получает конфликт и может подготовить новый reviewable результат. Проверены single-process shared worker и protocol retry; filesystem writers из разных приложений этим gate не подтверждены.
