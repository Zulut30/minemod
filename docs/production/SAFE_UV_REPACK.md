# Безопасная перепаковка UV

Studio 0.21 добавляет перепаковку выбранных кубов с сохранением рисунка. Core и HTTP MCP проверки прошли; focused packaged-сценарий проверил кнопку, undo/redo, экспорт и повторное открытие. Пункт 055 остаётся открыт до полного evidence точной source revision и hosted-проверок. Эта операция не присваивает художественную приёмку нейтральному «Листу».

## Контракт

Закрытая команда `repackUv` принимает существующие `cubeIds` и необязательный `shared`: `preserve-exact` по умолчанию сохраняет полностью одинаковые прямоугольники вместе; `split` разделяет поверхности. Частичные overlaps копируются в независимые позиции. Перепаковываются все шесть граней каждого выбранного куба. Геометрия, размер атласа, ширина/высота каждой грани и ориентация отражённых UV не меняются. Project format v3 сохраняется. Это адресная операция редактора, без нового shell/eval или доступа к файлам через MCP.

Исходные пиксели читаются до изменения любого UV. Все выбранные поверхности получают новые позиции в одной транзакции. Частично общие области можно скопировать в независимые позиции; невыбранная поверхность продолжает читать прежние пиксели. Полностью одинаковые исходные прямоугольники допускают сохранение общей позиции по явно заданному режиму. Блокировки агента, CAS, replay и rollback остаются обязательными; новая команда не получает разрешения обходить active repair.

Невыбранные UV и их пиксели защищены. Непрозрачный рисунок за пределами выбранных UV также резервируется, даже если текущая модель его не использует. Старые выбранные пиксели очищаются только там, где нет чужого потребителя. Между новыми гранями и чужими UV остаётся минимум один пустой пиксель. Это padding policy; игровой bleeding и mipmaps проверяются отдельно в 056.

## Размещение и пределы

Прямоугольники сортируются детерминированно по размерам, затем по ASCII IDs/именам граней. Размещение идёт от верхнего левого угла, без вращения, ресайза и изменения texel density. Prefix sum занятости позволяет проверять область без повторного прохода по её пикселям. Число поверхностей ограничено текущим контрактом: не более 256 кубов × 6 граней; атлас не больше 256×256.

До первого проверочного запуска зафиксированы пределы одной команды: `100663296` построенных prefix cells и `4000000` попыток размещения. Они публикуются через `studio://contracts/v1`, не принимаются из payload и не увеличены после проверок. `UV_PACK_FULL` и `UV_PACK_BUDGET` отвергают всю транзакцию с подсказкой уменьшить выделение либо сохранить одинаковые UV. Greedy размещение не обещает оптимальную упаковку. Автоматической смены разрешения и потери рисунка при отказе нет. Повтор упаковки уже размещённых поверхностей возвращает `NO_CHANGE`.

Перепаковка меняет explicit face UV, но не старый box-UV allocator добавления кубов. Она не гарантирует устранение `ATLAS_FULL` при создании нового куба. Смена разрешения и перестройка allocator требуют отдельной реализации.

## Работа в редакторе и рендер

Выберите кубы или часть модели, перейдите в «Текстура / UV» и раскройте «Упаковка UV выделения». Выберите обработку общих UV и нажмите «Перепаковать UV». Получается один шаг истории. Рисунок на невыбранных поверхностях и неиспользуемые непрозрачные пиксели атласа защищены.

Первое сравнение packaged GPU-снимков обнаружило расхождение при точном совпадении рисунка всех граней: изменение позиций UV влияло на края отрисованных поверхностей. Первоначальные PNG и отчёт сохранены в `output/playwright/uv-repack-055-104f671a/uv-repack/`, pixel diff показал 1950/1842/841/2318 отличающихся пикселя на front/back/side/perspective. После исправления nearest-preview сначала определяет целый texel в локальных координатах грани, ограничивает его прямоугольником и выбирает центр этого texel в атласе. Геометрия и экспортируемые UV не сжимаются на полпикселя. Исправление относится к Studio WebGL renderer, не к Minecraft renderer.

Focused проверка на пакете 0.21 `594ec823` подтвердила побайтное совпадение четырёх GPU-видов до/после перепаковки, после повторного открытия и после переноса с двумя отражениями UV. Сравнение всех 312 поверхностей исходного 52-кубового fixture и точных RGBA экспортированного PNG прошли. Полный набор приложения и hosted CI проверяются отдельно. Это fixture Aurora, а не художественная приёмка «Листа».

Регрессия смены проекта использует тот же cube ID и рисунок из четырёх цветных областей, последовательно открывая атласы 256 → 32 → 256. Она выявила сохранение uniform размера старого атласа в предыдущем шейдере; снимки сохранены в `output/playwright/uv-atlas-switch-055-11c50dd5/`. Сейчас размер берётся из текущего GPU sampler через `textureSize`, поэтому кэш материала не сохраняет чужой размер. Focused-сценарий `output/playwright/uv-repack-055-bcd1850b/uv-repack/report.json` подтвердил совпадение всех четырёх видов для трёх размеров/открытий и полный возврат исходного проекта. Атлас 256 в этой проверке используется дважды; это проверка переключения между двумя разрешениями.

## Проверка

Для каждой грани сравниваются точные RGBA до/после с учётом отражения UV. Проверяются общие и частично пересекающиеся исходные UV, прозрачность, padding, сохранение невыбранной части и неиспользуемого рисунка, отсутствие изменения геометрии и полные undo/redo. Нехватка места, неизвестные IDs, закрепления, stale revision, malformed input и превышение вычислительного бюджета должны сохранять документ и историю.

Через настоящий HTTP MCP проверены read-only preview, apply/replay, stale revision, export и отказ в active repair. В упакованном Studio проверены кнопка, сохранение/повторное открытие, четыре GPU-вида до/после, отражения и полный возврат исходного проекта. Локальные результаты и hosted CI связываются с точной source revision и ASAR. Художественная приёмка текстуры и authored Minecraft/JAR integration не присваиваются тестами упаковки.

Повторить focused-сценарий после сборки текущего пакета:

```powershell
corepack pnpm --filter @mcdev/model-editor package
corepack pnpm --filter @mcdev/model-editor verify:uv-repack
```

При исправлении renderer сверены [Three.js Texture](https://threejs.org/docs/pages/Texture.html), [Material.onBeforeCompile](https://threejs.org/docs/pages/Material.html#onBeforeCompile), текущий `map_fragment` закреплённого Three 0.186.1 и Context7. Guard на форму shader chunk требует новой проверки при его изменении.
