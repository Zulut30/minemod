# Состояние и локальный бюджет агента

Roadmap 040, Studio 0.18.0. Панель в настройках подключения показывает фактически наблюдаемые tool calls Studio: очередь, выполнение, завершение, ошибку и отмену. Время включает ожидание в очереди. Активный запрос имеет приоритет перед новой ожидающей правкой; запоздавшее завершение отменённого запроса не заменяет новый результат.

Токены и стоимость внешнего Codex/Claude Code всегда обозначены как неизвестные: текущий MCP-клиент не передаёт расход. Панель не оценивает процент готовности модели, внутреннее рассуждение AI, тариф аккаунта или действия клиента вне Studio. Число локальных MCP-сессий также не подтверждает, что внешний процесс сейчас работает: `client.close()` без DELETE оставляет сессию до idle TTL.

Раскрываемые подробности содержат остаток обычных HTTP-запросов текущей минуты (120), остаток запросов каждой локальной сессии (1024) и последние восемь операций. Остаток — наблюдение на время события или чтения подключения; новая минута отражается при следующем запросе. Резерв cancellation/DELETE описан в [continuation contract](SESSION_CONTINUATION.md), но не считается платным AI-бюджетом. В адресном repair остаётся отдельный предел принятых итераций пользователя.

При 404/429 отображается причина и способ восстановления: заново initialize, завершение прежней MCP-сессии или ожидание освобождения очереди/следующей минуты. После успешного допустимого запроса прежнее сообщение снимается. Прерванный HTTP response отменяет свой ожидающий запрос; приложение не обещает обнаружить завершение внешнего клиента, который не оставил ожидающий response.

После выхода собственного utility process приложение немедленно выключает отображаемый доступ, закрывает ожидающее скрытое окно снимка и завершает pending host requests с `SERVICE_UNAVAILABLE`. Новые обращения получают отказ сразу, а не ждут двадцатисекундный timeout. Поздние сообщения завершённого worker не возвращают доступ. Редактор можно закрыть и перезапустить для чтения доступной восстановительной копии. Сохранённый файл не переписывается обработчиком отказа; восстановительная копия остаётся последней успешно записанной версией, а не обещанием сохранения незавершённой записи.

Статус идёт через отдельный приватный worker → main → preload канал. Renderer получает только `{sequence,status}`; номер сохраняет порядок и отбрасывает старые/повторные snapshots. Изменения состояния сцены и её revision от этого канала не зависят. Обновление длительности раз в секунду выполняется внутри панели, без передачи полного проекта из worker.

Metadata ограничена 8192 bytes, восемью последними операциями и опубликованными caps сессий/HTTP. Имена инструментов и подписи берутся из фиксированного списка десяти tools; неизвестное имя заменяется общей подписью. В metadata отсутствуют исходный JSON-RPC ID, имя клиента, prompt, arguments, модели, PNG, URL и token. Callback в preload отбрасывает `IpcRendererEvent` и предоставляет unsubscribe. Delivery failure не прерывает атомарную правку.

Проверки: headless monitor и реальные HTTP/SDK continuation tests проверяют queued/running/result/cancel, caps, reconnect, ограниченный размер и отсутствие payload echo. Скрытый packaged EXE проверяет GUI-время, очередь перед native capture, PNG 1024×768, ошибку input, истечение MCP-сессии, сохранение исходника, завершение собственного utility process, закрытие capture и восстановление после перезапуска. Самостоятельный новый model turn, художественная и авторская игровая приёмка этим пунктом не подтверждаются.

Использование IPC сверено через Context7 и [официальное руководство Electron](https://www.electronjs.org/docs/latest/tutorial/security#20-do-not-expose-electron-apis-to-untrusted-web-content). Dependencies и lockfile не изменены. Полный local/hosted прогон точной source revision ещё выполняется; пункт 040 остаётся открытым до его завершения и записи evidence.
