# Полный ручной путь в Studio

Пункт 021, в работе. Проверяется новый пустой held-item, созданный через GUI: добавление куба, имя части, размер, положение, цвет, сохранение, смена документа, повторное открытие и экспорт. Терминал не входит в пользовательский путь. Developer test запускает собственный скрытый экземпляр упакованного EXE.

## Сценарий

«Новый» создаёт пустой проект, где экспорт отключён. «Добавить куб» создаёт геометрию и свободные UV. Выберите часть в дереве; имя, размеры и положение задаются в свойствах. Примените цвет и выполните «Сохранить как…», выбрав собственный `.mmeditor.json`.

«Открыть» восстанавливает документ с теми же IDs, формой, рисунком и именами. «Экспорт» записывает Minecraft JSON, PNG, `.bbmodel` и исходный item asset в отдельный versioned bundle. Отчёт о целостности не является художественной оценкой или разрешением на JAR-интеграцию.

Проверяемый новый предмет сохраняет текущие defaults имени и ID `mcdev:new_item`. Произвольное изменение item ID, игровых display transforms, authored blocks/armor/entities или загрузка `.bbmodel` этим пунктом не реализуются. Оригинальный проект редактора содержит semantic parts; item source экспорта хранит геометрию и texture plan, для дальнейшей ручной правки следует сохранять `.mmeditor.json`.

## Evidence

`check-manual-desktop.mjs` изменяет документ только кнопками и полями. Bridge `inspect` используется для чтения и сравнений. Native dialog mocks возвращают только пути тестовых файлов и решение discard при смене первоначального примера; geometry или pixels напрямую не записываются.

Сценарий начинает с пустой сцены, сохраняет один новый предмет, переключается на другой пустой документ, повторно открывает именно сохранённый, экспортирует и перезапускает Studio. Проверяются точные bytes собственного проекта, чистое состояние после save/open, integrity manifest и каждого фактически записанного файла, source/export equality, сохранность оригинала и restart recovery. Скриншот получен из того же скрытого окна.

Ранее существующие packaged suites дополнительно проверяют cancel, Save As, неверный ввод, stale open/save, backup recovery, UV/painting, undo/redo и человеческую историю. Это автоматизированная проверка GUI; внешний пользовательский пилот и наблюдение за затруднениями человека остаются пунктом 092.

Первый helper неверно прочитал расположение source path в manifest и отказал после уже выполненного GUI экспорта. Исправлено чтение `manifest.assets[0].source`; лог отказа сохранён, файлы не подменялись. Локальный corrected GUI PASS, hosted нового test source ещё ожидается.
