# Контракт первого production-релиза

Версия контракта: 1. Дата: 4 октября 2026 года. Roadmap: пункт 001.

Этот документ задаёт одну матрицу платформ для MineMod Studio и генератора. Он не присваивает текущей экспериментальной сборке статус production. Источник игрового baseline — [ADR-0004](../decisions/0004-fabric-1.20.1-production-baseline.md).

## Матрица платформ и доказательств

| Компонент | Target первого выпуска | Что подтверждено сейчас | Что ещё требуется для production |
|---|---|---|---|
| Desktop Studio | Windows 11 x64 | Пакет 0.5.1 и его локальный packaged E2E; SHA-256 EXE/ASAR повторно сверены 4 октября | Clean-machine установка, hosted Windows CI, обновление/rollback и пользовательский пилот |
| Среда локальной проверки | Windows 11 Pro x64, version 10.0.26200, build 26200 | ОС текущей проверки зафиксирована отдельно от возможностей приложения | Проверки поддерживаемых builds Windows 11 и заявленного аппаратного профиля |
| Node/pnpm для разработки | Node 24.11.0 / pnpm 11.8.0 | Зафиксированы в `package.json` и lockfile | Проверяемый bootstrap из clean checkout; это не требование к конечному пользователю готового EXE |
| Сборка игрового проекта | Linux x64 с доверенным Java/Gradle toolchain | Runner проверяет эту платформу; Windows-процесс Studio не является игровым runner | CI и проверяемое подключение разрешённого Linux runner из Windows-пути; отсутствие runner должно объясняться явно |
| Игровой baseline | Minecraft 1.20.1, Fabric Loader 0.19.3, API 0.92.11+1.20.1, Loom 1.6.12, Gradle 8.7, Temurin 17.0.19+10 | Exact tuple зафиксирован в `packs/fabric-1.20.1/pack.json`; pack имеет экспериментальный статус | Server GameTests, client harness, hosted CI, dependency/license review и пять dogfood-проектов |
| Codex и Claude Code | Установленные клиенты с разрешённым MCP-доступом к проекту | MCP SDK и существующая desktop surface проверялись локально | Отдельный реальный сеанс создания модели каждым клиентом на зафиксированной версии |
| Другие desktop ОС/архитектуры | Не заявлены в первом выпуске | Нет release-доказательств в этом контракте | Отдельная матрица и проверки до добавления поддержки |
| NeoForge 26.1.2 / Fabric 26.2 | Regression backends | Существующие fixtures сохраняются | Regression CI; эта строка не заявляет production parity |

Локальное доказательство desktop-пакета сохранено в [studio-0.5.1-local.json](evidence/studio-0.5.1-local.json). Это импорт результатов уже выполненных тестов с новой проверкой hashes; новый игровой тест или новая художественная приёмка этой записью не создаются.

## Обещание пользователю

- Ручные операции и агентные операции изменяют один проект через валидируемые транзакции. Есть сохранение, восстановление, история, границы прав и понятные ошибки.
- Каждый заявленный target имеет собственные правила geometry/texture/runtime. Экспорт held-item не выдаётся за wearable-броню или block model.
- Пользователь получает editable source, runtime files и evidence. Generic mesh/image-to-3D не обещается как готовый production-путь.
- Выпускаемые модели проходят техническую проверку, художественную оценку человеком и игровые проверки. Ни кубы, ни корректный JSON, ни изображение концепта не подтверждают готовую 3D-модель.
- В production JAR нет placeholder-ассетов. Подключение авторского bundle выполняется явно через versioned contract без подмены JAR и изменения trusted pack.
- Package и publish разделены. Итоговая публикация относится к точному проверенному digest и выполняется после предусмотренной человеческой приёмки.

## Неизменяемые границы

Внешний агент не получает generic shell, произвольный Blender/Blockbench eval, установка зависимостей через MCP или доступ к любым путям компьютера. Входные данные и задания ограничены по объёму и времени. Секреты не попадают в projects, exports и диагностические bundles.

JEI/EMI/Jade остаются optional там, где соответствующий version-tested adapter реализован. Неподдерживаемая интеграция отклоняется, а не добавляется по предположению. Отсутствие optional-мода проверяется в игре.

Смена версии в exact tuple оформляется отдельной compatibility revision. Контракт не разрешает удалить существующие regression checks или назвать их доказательством 1.20.1.

## Приёмка пункта 001

Одна матрица выше различает target, фактическое локальное доказательство и незакрытые release gates. На момент её записи desktop version/hashes/report и ОС сверены; pack/ADR прочитаны из текущего дерева. Проверка документа: все локальные ссылки существуют, в roadmap ровно 100 пунктов, отметка пункта 001 не закрывает другие пункты. Источник secure desktop boundary дополнительно сверён через Context7 с [официальной документацией Electron](https://www.electronjs.org/docs/latest/tutorial/security).
