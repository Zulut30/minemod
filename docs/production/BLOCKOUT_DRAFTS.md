# Три направления формы и объём «Листа»

Roadmap 036: **техническая приёмка пройдена**. В Studio 0.16.0 проверены самостоятельный Codex model turn с тремя редактируемыми формами и полный 19-subreport packaged suite локально и в hosted Windows CI точного коммита `012d2b5`. Пункт закрыт по функциональному workflow; художественная приёмка и authored Minecraft acceptance ещё не получены. Общий CI остаётся failed из-за checksum старого regression target Fabric 26.2. Пользователь выбрал направление A — «Лист»; это не approval готовой модели.

В репозитории сохранены оригинальные данные трёх нейтральных форм: [Лист / Клык / Раскол](../../fixtures/production/weapon-blockouts.v1.json). Отличаются геометрия и силуэт, материал общий. [Оригинальный AI-концепт](../../fixtures/production/concepts/weapon-directions-20261005.png) сохранён побайтно с [provenance](../../fixtures/production/concepts/weapon-directions-20261005.provenance.json). Он задаёт 2D-направление, не является готовой 3D-моделью. Сторонние references не использованы; независимая проверка прав не выполнена.

После выбора A подготовлена [итерация объёма](../../fixtures/production/leaf-volume.v1.json): тонкий внешний край, центральный гребень на обеих сторонах, наклонённая к рукояти гарда и ромбовидное навершие. Исходник v2 остаётся отдельным вариантом. Промежуточные попытки сохранены: первая содержала зазор 0.05 единицы под гардой; он обнаружен и исправлен. Длинный тонкий кончик также укорочен. Нейтральный материал позволяет увидеть конструкцию до покраски.

## Воспроизведение

Используйте закреплённые Node 24.21.0 и workspace dependencies. Папка результата должна быть новой и находиться внутри `output/`:

```powershell
node --experimental-strip-types scripts/author-weapon-blockouts.mjs output/model-editor/three-new-drafts
node --experimental-strip-types scripts/author-weapon-blockouts.mjs output/model-editor/leaf-new-draft fixtures/production/leaf-volume.v1.json
node apps/model-editor/scripts/review-blockout-drafts.mjs output/model-editor/leaf-new-draft
node --experimental-strip-types scripts/verify-blockout-construction.mjs output/model-editor/leaf-new-draft/b.mmeditor.json
```

Для review нужен локально упакованный Studio из `output/model-editor/latest-build.json`. Helper запускает собственный скрытый экземпляр, использует закрытые MCP captures и завершает только свой процесс. Он не управляет рабочим столом. Сохраните `.mmeditor.json` вместе с его папкой `.assets`; в каждом проекте есть независимые снимки вариантов и исходный концепт.

В исходных fixture-примерах геометрия создаётся через `EditorSession` с actor `agent`: `add`, `transform`, `recolor`, `pivot`, `rotate`, preview и apply. Имена групп, бриф, концепт и снимки этих исходных примеров готовит локальный авторский workflow. Они **не являются самостоятельным CLI/MCP-сеансом генерации**.

## Агентные снимки в Studio 0.16.0

Подключённый агент теперь может добавить новый снимок текущей сцены командой `draftVariant` через обычные `studio_changes_preview` и `studio_changes_apply`. Команда принимает только новый `variantId`, label до 32 и note до 300 символов. Она не принимает model, filepath или approval, не меняет существующие snapshots и сохраняет текущие замки и покраску. Снимок получает фиксированный префикс «ИИ-черновик» и пояснение о незавершённой художественной приёмке.

Максимум — три ИИ-черновика и четыре снимка всего. Checkpoint, восстановление, удаление, бриф, концепты и замки остаются ручными. Для следующей формы агент изменяет незакреплённую рабочую геометрию, оставляя предыдущий снимок независимым. Активное задание адресного repair запрещает создание snapshots. Ошибки, CAS, атомарный rollback и точный replay используют общий engine.

Лимит относится к одновременно сохранённым снимкам, не к общему числу попыток генерации. Агент может отменить собственное недавнее добавление через обычную историю, пока сверху нет ручного действия; ручной исходник и человеческую историю он отменять не может. Бюджет всего сеанса относится к отдельному пункту 040.

Проверка дублей сравнивает углы размещённых твёрдых кубоидов с учётом origin/size/rotation/pivot/inflate, игнорируя IDs, UV и цвет. Полное дублирование того же кубоида также не создаёт новую форму. Числа нормализуются с точностью 1e-6 единицы. Это ограниченный технический фильтр: изменение разбиения кубоидов или небольшой сдвиг может пройти его, даже если художественно силуэт почти тот же. Сравнение изображений и human review обязательны для качества.

Формат проектов остаётся v3: новые snapshots используют существующие поля, старые файлы мигрируются по прежнему контракту. Для новой MCP-команды требуется Studio 0.16.0. Новых зависимостей, shell/eval или agent file access нет.

```powershell
corepack pnpm --filter @mcdev/model-editor package
corepack pnpm --filter @mcdev/model-editor verify:blockouts
# Самостоятельный сеанс установленного Codex CLI, с исходным концептом и пустой сценой:
$env:MINEMOD_CODEX_ENTRY = 'C:/Users/zulut/AppData/Roaming/npm/node_modules/@openai/codex/bin/codex.js'
node --experimental-strip-types apps/model-editor/scripts/verify-codex-session.mjs --blockouts
```

Последняя команда использует существующий local CLI login и настройки модели; глобальная конфигурация не меняется. В изолированном сеансе доступны только закрытые MCP-операции Studio. Оператор создаёт пустой ручной baseline, бриф и импортирует оригинальный концепт; геометрию и три черновика должен создать CLI. Техническое успешное завершение не присваивает художественную оценку.

## Что проверено

- Три формы воспроизведены с теми же geometry hashes, что у сохранённых v2-черновиков; каждую можно редактировать и экспортировать в нативный item JSON, PNG и `.bbmodel`.
- На Studio 0.15.0 получены настоящие MCP PNG: восемь ракурсов, силуэт и обзор с 32/64 px. Чтение сохраняет сцену. Для пары v2/v3 используется одна и та же объединённая область кадра.
- Новый SDK-тест создаёт три snapshots именно через MCP, проверяет read-only preview/replay, защиту ручного исходника, закреплённой рукояти и одного покрашенного пикселя, лимиты и запрет restore/delete агентом. Сохраняет 30 настоящих PNG, выбирает вариант в скрытом GUI, делает undo, проверяет сохранение/restart и bundle-v1. Это функциональный model workflow, не самостоятельный model turn или человеческое approval.
- SAT-проверка ориентированных твёрдых кубоидов подтверждает связность исправленной версии. Промежуточный вариант с зазором отклонён. Контакт только ребром или точкой не считается креплением. Метод не учитывает прозрачные отверстия текстуры и не оценивает смысл пересечений.
- Original PNG, sidecars, source projects, возвращённые captures и native exports проверены по SHA-256. [Evidence](evidence/blockouts-036.json) сохраняет границы этих результатов.

CLI-сеанс и SDK-проверка — разные доказательства: CLI создаёт формы самостоятельно; scripted GUI проверяет доступность ручных операций. Ни один результат не присваивает художественное approval. Визуально формы остаются простыми черновиками; работа над пропорциями и гардой продолжается после человеческой оценки.

[Hosted run 37344629791](https://github.com/Zulut30/minemod/actions/runs/37344629791) проверил точный source `012d2b5`: control-plane, Windows Studio, Fabric 1.20.1 / Java 17, NeoForge и client-smoke прошли. Windows повторил все 19 subreports; 30 PNG нового agent workflow скачаны и независимо сверены по hashes. Source JSON, bundle и trace не входят в hosted retention: их точные проверки выполнены самим helper, локальные файлы сохранены отдельно. Проверены чистые checkout трёх заданий и совпадение 20 source/fixture hashes с Git blobs. Native proof содержит шесть generated source-файлов, JAR, два infrastructure GameTests и dedicated-server lifecycle; авторские мечи этим путём не интегрированы в Minecraft.

Общий workflow failed: legacy Fabric 26.2 получил checksum mismatch `net.minecraft:minecraft-common-043a8b3edf:26.2`. Текущий observed SHA-256 — `b968fe61934399eb614e9c042f821d7ea93a6780f892adab3056fe50bba6c0a0`; причина не установлена, checksum policy не изменена. Это ограничение общего CI сохранено в evidence и не выдано за успешный production release.

Эти output-файлы локальны и не входят в checkout; исходные fixture и команды выше позволяют создать новый набор. Число кубов, связность и корректный JSON не доказывают художественное качество. Форма ещё ожидает человеческой оценки; текстура не принята, модель не интегрирована в JAR и не проверена в игре. Следующий художественный шаг зависит от оценки нейтрального объёма.
