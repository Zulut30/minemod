# Локальная перекраска с сохранением цветов

Studio 0.20 добавляет `preserveColors` к закрытой команде `recolor`. В свойствах выделения откройте «Сохранить цвета» и отметьте цвета руны, кристалла или блика. «Применить цвет» тонирует оставшиеся непрозрачные пиксели выбранных кубов, сохраняя градации яркости. Защищённый RGB и прозрачность остаются прежними. Выбор всех доступных цветов отключает пустую операцию.

Это выбор конкретных цветов, включая все их пиксели внутри выделения. Одинаковый RGB металла и руны нельзя разделить этой настройкой; для этого нужен отдельный цвет, поверхность или ручная покраска. Настройка живёт в интерфейсе, привязана к выделению и не добавляет metadata в `.mmeditor.json`. Результат сохраняется обычной текстурой; формат проекта v3 прежний.

```json
{
  "type": "recolor",
  "cubeIds": ["blade_mass"],
  "color": "#804020",
  "preserveColors": ["#FFFF00"]
}
```

Перед применением агент читает актуальные cube IDs и палитру. Используются существующие `studio_changes_preview` → `studio_changes_apply`; набор MCP tools и полномочия прежние. До 32 уникальных `#RRGGBB`, регистр сравнивается без различия. Сервер отвергает неверный формат, превышение лимита и дубликаты, включая пару разных регистров. Без поля или с `[]` сохраняется прежнее поведение команды.

Яркость основы рассчитывается по оставшимся пикселям материала. Сохранённая светлая руна не затемняет новый тон основы. Защита распространяется на цвет в выбранной области, а общие UV с невыбранными кубами по-прежнему требуют отдельной развёртки. Закрепления, repair scope, CAS, replay и лимит 32 используемых цветов остаются действующими. Когда весь непрозрачный материал сохранён, core возвращает `NO_CHANGE`; документ и история не меняются. Переполнение новой палитры отклоняет всю транзакцию.

## Проверки и границы

Core test использует серую основу `#808080`, четвертную тень `#202020`, светлый жёлтый знак `#ffff00` и прозрачный пиксель. При тоне `#804020` ожидаются точные RGBA основы `[128,64,32,255]`, тени `[32,16,8,255]`, знака `[255,255,0,255]` и прозрачности `[0,0,0,0]`. Они проверены в распакованном PNG экспортёра. Соседняя часть, модель и parts сохраняются; undo/redo восстанавливают полные данные. Проверены старый режим, 33 сохраняемых цвета, дубликаты, пустая операция и атомарное переполнение палитры.

Packaged desktop scenario проверяет scripted UI действие, изоляцию выделения, отключение пустого действия, HTTP MCP preview/apply и полный undo. Реальный MCP export проверяется по SHA-256 PNG и точным RGBA сохранённых/невыбранных пикселей. Это техническая проверка управления цветом. Художественная читаемость рисунка, материал в игровом свете и authored JAR integration остаются отдельными gates; пункт 057 открыт до полного evidence.

Контракт сверялся с Context7 и официальной [Zod API документацией](https://zod.dev/api). Используется закреплённый Zod 4.4.2; новая dependency и изменение lockfile отсутствуют. Актуальная документация описывает более новую версию, поэтому лимиты и refine дополнительно проверены установленным parser и HTTP service.
